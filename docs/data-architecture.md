# 드림캐스팅 데이터 구조 설계

작성: 2026-11-22. 전제: 지금은 무료, 비상업 포털로 운영하고, 상업화(데이터 판매, 광고, 라이선스 계약)로 바꿀 때 스키마나 알고리즘을 다시 만들지 않도록 처음부터 그 구조로 짓는다.

## 1. 원칙
1. 외부 호출, 사실 정리, 점수 계산, 문장 생성을 층으로 나눈다. 한 함수에서 섞지 않는다.
2. 모든 데이터는 출처(`data_source`)를 갖고, 출처의 라이선스 등급이 파생 데이터까지 따라간다.
3. 상업 이용 가능 여부는 데이터가 아니라 플래그(`commercial_ok`, `resale_ok`)로 관리한다. 계약하면 플래그만 바꾼다.
4. 외부로 나가는 데이터는 `mart` 스키마의 집계 뷰뿐이다. 개인 단위 행은 나가지 않는다.
5. 소개 문장은 근거 데이터가 있을 때만 만든다. 근거 없는 문장은 품질 검사에서 걸린다.
6. 쓰기는 서버와 RPC만. 새 테이블은 RLS를 켜고, 공개 사실(인물, 작품, 출연, 리메이크)만 읽기를 공개한다.

## 2. 층 구조
| 층 | 테이블 | 역할 |
|---|---|---|
| 수집원 | `data_source` | 출처 코드, 라이선스 등급, 상업 가능 여부, 보관 기한, 출처 표기 |
| 원본 보관소 | `raw_fetch` | 받은 응답 원문. 보관 기한이 있는 출처는 `expires_at` 자동 설정, 매일 삭제 |
| 정본 데이터 | `people`, `work`, `credit`, `override` | 인물 하나에 TMDB ID와 위키데이터 ID를 묶음. 분류는 여러 개. 운영자 수정은 데이터로 |
| 리메이크 마트 | `adaptation`, `story_character`, `character_map`, `casting_outcome`, `work_perf` | 원작과 리메이크 관계, 판본 간 같은 배역 연결, 실제 캐스팅 시점 특징, 흥행과 평점 |
| 신호 | `signal` | 인물별 시계열(뉴스 언급, 조회수, 인기, 트렌드) |
| 자체 행동 | `events`, `ux_events`, `out_clicks`, `votes` | 1차 데이터. 판매 가능 데이터의 원천 |
| 선발과 소개 | `candidates` | 규칙 통과 후 점수화. 이유 문장은 근거 연결 |
| 운영 | `job_run`, `qa_result` | 작업 기록, 매일 품질 검사 결과 |
| 판매 골격(비활성) | `data_client`, `data_client_key`, `data_api_usage`, 스키마 `mart` | 업체, 키 해시, 사용량. 지금은 비활성 |

## 4. 갱신 주기
| 데이터 | 주기 | 방식 |
|---|---|---|
| 투표, 클릭, 머문 시간 | 즉시 | 트리거로 집계 갱신, 화면 실시간 반영 |
| 뉴스, 트렌드, 네이버 | 1시간 | 현재 후보 세트 인물과 상위 500명만 |
| 유튜브 | 하루 | 검색 하루 100회 안에서 순환, 조회수는 저렴한 조회로 |
| TMDB 인기, 위키 조회수 | 하루 | |
| 출연, 국적 같은 사실 | 변경 시 | |
| 후보 세트 | 주간 기본, 사건 발생 시 해당 작품만 즉시 | 투표 비교 가능성 유지 |
| 주간 스냅샷 | 주간 | 판매와 추이 비교의 기준점 |

## 5. 개인정보와 동의
1. `profiles`에 통계 작성 동의 시각, 제3자 제공 동의 시각, 선택 입력(연령대, 성별, 지역)을 둔다.
2. 집계 칸 인원이 50명 미만이면 숨긴다.
3. 개인정보처리방침과 이용약관에 통계 작성과 집계 제공 조항을 먼저 넣는다. 고지 전에 모은 데이터는 나중에 쓰기 어렵다.

## 6. 진행 단계
1. 1단계(완료 2026-11-22): 출처표, 원본 보관소, 정본 인물 병합(cast_pool 4,150행을 people 3,752명으로), 작품과 출연, 리메이크 마트 테이블, 운영자 수정표, 신호, 작업 기록, 품질 검사 함수와 매일 실행, 판매 골격. 남은 일: 약관과 동의 화면.
2. 2단계: 출연 기록 적재, 리메이크 사례 적재(올드보이, 인턴 등), 매시간 신호 수집, `recommend`가 DB만 읽도록 전환, 이유 문장에 근거 ID 연결, 품질 검사 통과 시에만 새 세트 공개.
3. 3단계: 판매용 `mart` 상품, 파트너 API(`/v1`, 키 해시, 범위, 호출 한도, 사용량 청구), 대량 파일 제공.
