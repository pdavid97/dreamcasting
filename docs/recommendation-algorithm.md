# 드림캐스팅 추천 알고리즘 설계안 (후보 추천, 후보 소개, 작품 추천)

작성: 2026-11-22. 전제: 데이터 구조는 dreamcasting/data-architecture.md(정본 people, work, credit, signal, events, collection, adaptation)를 따른다.

## 1. 목표와 지표
| 대상 | 무엇을 맞히나 | 1차 지표 | 보조 지표 |
|---|---|---|---|
| 후보 추천 | 이 배역에 유저들이 실제로 표를 줄 사람 | 세트 내 득표 점유, 세트 밖 유저 추가 후보 비율(낮을수록 좋음) | 실제 캐스팅 발표와의 적중, 다양성 |
| 후보 소개 | 왜 이 사람인지 납득과 재미 | 소개를 본 뒤 투표율, 머문 시간 | 후보 간 문장 중복률(낮을수록 좋음) |
| 작품 추천 | 다음에 누를 작품 | 카드 클릭률, 투표 완료율, AV룸 담기 | 재방문, 세션당 작품 수 |

## 2. 후보 추천: 4단 구조(넷플릭스식 후보 생성, 점수, 재정렬, 설명)
1. 후보 생성(수천 명에서 수백 명으로): 여러 생성기를 합친다.
   - 원작 배우 닮은꼴: 원작 배우와 공출연 그래프 거리, 같은 작가와 감독 작품 출연, 같은 직업 계열 배역(형사, 재벌, 사극 왕 등)
   - 실제 리메이크 패턴: adaptation과 casting_outcome에서 학습한 "원작 배우 대비 나이 차, 인지도 비율" 분포에 맞는 사람
   - 유저 협업 필터링: 이 배역에 A를 찍은 유저가 다른 배역에서 같이 찍은 사람(아이템 간 공동 투표)
   - 화제 신호: 최근 7일 뉴스 언급, 위키 조회수 상승세(signal)
   - 유저 제안: 세트 밖에서 유저가 추가한 후보(add_candidate)는 그 자체로 강한 신호
2. 점수(수백 명에서 수십 명으로): 학습형 순위 모델. 특징은 아래 표, 정답은 "노출 대비 득표"와 "실제 캐스팅 결과".
3. 재정렬(6명 세트): 칸 규칙(정석 3, 화제 1, 케미 1, 와일드카드 1)과 다양성 제약(같은 사람 반복 노출 감점, 나이대와 이미지 분산), 탐색 칸(새 얼굴에 일정 비율 노출하는 밴딧).
4. 설명: 점수에 가장 크게 기여한 특징 2개를 근거 문장으로 바꾼다(3장).

| 특징 묶음 | 예시 | 출처 |
|---|---|---|
| 적합도 | 원작 배우와 나이 차, 성별, 국적권, 배역 계열 경력 수 | people, credit |
| 관계 | 원작 배우와 공출연 횟수, 상대역 후보와 공출연, 같은 감독 작품 수 | credit 그래프 |
| 인기와 추세 | TMDB 인기, 뉴스 언급 7일 변화율, 위키 조회수 | signal |
| 연기 평판 | 광장 연기 점수, 작품 평점 가중 평균 | perf_scores, work_perf |
| 유저 반응 | 노출 대비 득표, 다이얼에서 머문 시간, 건너뛰기 | events, ux_events, votes |
| 실제 업계 패턴 | 리메이크 실사례의 나이 차와 인지도 비율과의 거리 | casting_outcome |

학습 데이터가 쌓이기 전(콜드 스타트)에는 지금처럼 규칙 가중합을 쓰고, 투표가 배역당 수백 건을 넘으면 가중치를 로지스틱 회귀로 맞춘 뒤 경사 부스팅 순위 모델로 옮긴다. 모든 모델은 SQL과 Edge Function 안에서 돌 수 있는 크기로 유지한다.

## 3. 후보 소개를 후보마다 다르게: 근거 카드 방식
지금 소개가 비슷한 이유는 "나이 비교" 같은 공통 근거가 거의 모든 후보에 있기 때문이다. 해결책은 "후보끼리 비교해 그 사람에게만 있는 근거"를 고르는 것이다.
1. 근거 후보 만들기(각 후보마다 10개 안팎): DB에서 사실을 뽑는다. 예: 원작 배우와 공출연 작품, 같은 계열 배역 경력, 같은 감독 작품, 상대역 후보와 호흡, 최근 상승세, 광장 연기 점수 순위, 실제 리메이크 사례와의 유사도, 팬 수, 유저 추천 한마디.
2. 희소성 점수: 같은 세트 6명 중 그 근거를 가진 사람이 적을수록 높게(1명만 가진 근거가 최고점). 숫자형 근거는 세트 안 순위로 바꾼다(예: "이 세트에서 사극 경력 1위").
3. 선택 규칙: 후보마다 희소성 높은 근거 2개를 고르되, 같은 세트 안에서 같은 근거 유형이 2명을 넘지 않게 한다.
4. 문장화: 유형별 문장 틀을 여러 개 두고, 숫자와 작품명은 근거 행에서만 넣는다. 근거 행 ID를 함께 저장해 품질 검사에서 사실 여부를 자동 확인한다.
5. 비교 문장: "이 세트에서 원작 나이와 가장 가까운 사람", "6명 중 유일하게 감독과 두 번 작업한 사람"처럼 세트 안 비교를 우선한다.

## 4. 작품 추천(홈 덱과 작품 상세의 "다음 볼 작품")
1. 유저 취향 벡터: 투표한 배우와 작품의 장르, 원작 매체, 리메이크 방향, AV룸에 담은 작품, 머문 시간, 건너뛴 작품을 묶어 만든다.
2. 후보 생성: 내가 표를 준 배우가 후보인 다른 작품, AV룸 작품과 같은 장르나 같은 원작자, 비슷한 유저가 투표한 작품, 화제 상승 작품, 마감 임박 작품.
3. 순위: 클릭과 투표 완료 확률 모델. 신규 유저는 인기와 마감 임박으로, 행동이 쌓이면 개인화 비중을 높인다.
4. 재정렬: 같은 분류가 연속 3개를 넘지 않게, 새 분류 하나는 꼭 섞기(탐색), 이미 투표 끝난 작품은 결과 보기 카드로 전환.
5. 연결 동선: 작품 상세에서 출연진, 그 배우가 후보인 투표, 리메이크 계보로 이어지게 해 플랫폼 안에서 계속 돈다(2026-11-22 1차 반영).

## 5. 학습과 검증 루프
- 매일: 노출, 투표, 머문 시간, 추가 후보를 events에 집계.
- 매주: 가중치 재학습과 A/B 비교(세트 득표 점유, 유저 추가 후보 비율). 품질 게이트를 통과한 결과만 공개.
- 실제 캐스팅 발표가 나오면 casting_outcome에 넣고 "광장 예측 대 실제" 비교를 콘텐츠와 학습 정답으로 동시에 쓴다.

## 6. 진행 순서
1. 근거 카드 방식 소개(3장) 적용: 출연 기록 적재가 끝나는 대로.
2. 아이템 간 공동 투표 생성기와 노출 대비 득표 특징: 투표가 쌓이는 대로.
3. 작품 추천 개인화: AV룸 담기와 머문 시간 기록이 쌓인 뒤.
